# 피아노롤 개인 초안

MIDI 편집은 브라우저 복구본과 서버의 개인 초안으로 저장한다. 자동 저장이나 뒤로가기는 공동 작업의 실제 클립을 수정하지 않는다. 기존 저장 버튼은 초안을 실제 레이어에 반영하고 스튜디오로 돌아간다. 작업 제출은 최신 초안 반영과 기존 기여 제출을 서버에서 한 트랜잭션으로 처리한다.

## 사용자 동작

- 노트 추가/이동/길이 변경/삭제는 메모리 상태와 브라우저 복구본을 함께 갱신한다. 빈 노트 목록도 유효하다.
- 마지막 변경 1초 후 서버에 자동 저장하고, 편집이 이어질 때는 5초마다 저장을 시도한다. 화면이 숨겨지거나 연결이 회복될 때도 저장을 시도한다.
- 뒤로가기는 저장 큐를 비운 뒤 이동한다. 서버 저장에 실패해도 브라우저 복구본이 있으면 이동할 수 있다. 브라우저에도 저장하지 못한 미저장 변경이 있을 때만 beforeunload 경고를 사용한다.
- 같은 곡에 다시 참여하면 스튜디오에서 개인 초안의 이어하기를 제공한다. 빈 레이어만 만든 뒤 나갔어도 기존 레이어에서 작곡을 재개할 수 있다.
- 서버 저장 실패와 저장 중, 임시 저장 완료 상태를 표시한다. 실패 시 복구본을 유지하고 다시 저장한다. 권한/검증 같은 재시도로 해결되지 않는 4xx 오류는 주기적으로 재시도하지 않는다.
- 충돌 시 자동 저장을 멈추고 복구본 다운로드, 내 작업으로 저장, 서버 초안 불러오기를 제공한다. 닫힌 초안을 새 초안으로 되살리거나 원본 변경을 무시하는 반영은 거부한다.
- 초안 버리기는 확인 후 지정한 버전을 버린다. 다른 기기에서 더 최신 버전으로 바뀌었다면 먼저 해당 작업을 확인해야 한다.

## 구성

- `src/features/composition/editor-draft.ts`: React와 분리된 저장 큐, 버전/재시도 상태, 브라우저 복구본 검증. 요청 중 추가된 편집을 다음 요청으로 저장하고 응답 유실 후 같은 mutationId로 재시도한다.
- `src/features/composition/use-editor-draft.ts`: 초기 복원, 1초/5초 자동 저장, 이탈/연결 복구 이벤트, 명시적 저장/버리기.
- `src/features/composition/project-editor-drafts.ts`: 제출/발행 전 브라우저 작업 동기화. 충돌 시 덮어쓰지 않고 중단한다.
- `src/lib/api/composition-drafts.ts`: 개인 초안 API.
- `src/features/screens/studio-screens.tsx`: 저장 상태, 이어하기, 개인 초안 제출/발행 화면.

복구본 키는 `glitched.editor-draft.v1:{userId}:{projectId}:{trackId}:{clipId|new}`다. 탭별 보조 복구본을 따로 유지해 충돌한 두 작업을 모두 보존한다. 서버가 확인한 내용과 다른 미저장 편집은 완료 시에도 지우지 않는다. 계정이 바뀌면 기존 편집 화면을 다시 마운트하고 다른 계정의 토큰으로 이전 작업을 저장하지 않는다.

서버 초안이 있으면 다른 기기에서도 같은 숏폼/프로젝트에 재진입해 이어서 작업할 수 있다. 현재 화면 구조에 맞춰 곡 단위로 초안을 조회하며, 전체 곡의 초안을 모아 보여주는 별도 보관함은 제공하지 않는다.

## 검증

- `npm test`: 저장 큐의 순서, 응답 유실 재시도/재진입, 빈 노트, 저장 공간 실패, 계정 분리, 다중 탭 충돌, 완료 기록 처리, 기존 작곡 흐름.
- `npx tsc --noEmit`, `npm run lint`, `npm run build`.
- 실제 StudioScreen/NoteEditorScreen을 로컬 테스트 API에 연결한 화면 검증: 노트 입력 직후 뒤로가기, 새로고침 후 이어하기, 서버 저장 실패 중 새로고침 후 두 노트 복원, 연결 회복 후 동기화, 제출 시 클립 한 개에 두 노트 반영 및 PENDING 전환. 검증용 페이지와 API는 제품 코드에 포함하지 않는다.

백엔드의 새 초안 API와 editor_drafts 테이블을 먼저 배포해야 한다. 백엔드 저장소의 `docs/editor-drafts.md`, `docs/editor-drafts.sql`을 참고한다. 적용 범위는 피아노롤 MIDI이며 녹음 중인 원본 오디오/업로드 도중의 복구, 전체 초안 보관함과 자동 만료 정책은 포함하지 않는다. 기존 승인된 클립의 명시적 수정 정책은 유지한다.
